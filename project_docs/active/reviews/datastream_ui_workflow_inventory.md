# Datastream UI workflow and feature inventory

This review traces the app shell, the user actions it renders, and the data each action consumes. It covers product capabilities discoverable from the normal application. A component, API, or roadmap entry alone is insufficient evidence of a working control.

## How the data workflow works

| Stage | What the user sees | What the app does |
| --- | --- | --- |
| Attach data | Use **Upload data**, open a named entry from **Data Hub**, or use a connection form in **Data Tools**. | File upload creates the internal source and working context. Data Hub open restores the chosen entry, all working rows, source identity, and any saved model. REST and SQL imports use an older attachment path without the durable workspace envelope. |
| Confirm what is open | **Workspace** shows the working dataset name, row and field counts, and the associated Data Hub name when present. It offers Refine, Inspect rows, and Browse data tools. | These labels describe the active data in context. Navigating between destinations leaves that context available. |
| Inspect or filter | **Data Tools** opens on the working rows in a paged table. **Filter rows** supports several preview rules. Column profile and Duplicate rows check the complete loaded data. | Filters change the view. To save a row-selection change, apply a **Filter Rows** step in Power Query. Column profiles count filled and empty cells and frequent values. Duplicate checks show matching rows and their original positions. |
| Check values, keys, and totals | Use **Validate values** to see failed rows, **Check keys** to find missing or repeated keys, and **Summarize rows** to compare counts, totals, and averages by one or two fields. | These tools read all loaded working rows. Preview filters and paging leave the checked row set intact. Results are for inspection before refining, choosing join fields, or analyzing the data. |
| Change the data | **Workspace → Refine data** or **Data Tools → Power Query** opens the editor in Data Tools with the working dataset, its fields, and up to 100 loaded rows. Add steps, run a preview, and apply the result. | For a managed source, the server runs the recipe against the full source identified by its workspace, version, and source IDs. Apply updates the working dataset and keeps the editor in Data Tools. Save Dataset records the result in Data Hub. |
| Model and save | **Data Model** adds sources, relationships, and Business Object definitions. **Save Dataset** creates a named Data Hub entry, updates its selected revision, or saves a copy. | Saving a source or refined copy preserves the working rows. A live model retains its source references, relationship scope, and definitions. The catalog changes after a confirmed save. |
| Resume and analyze | **Data Hub → Open dataset** returns to Workspace. **Analytics** uses the normal navigation and shows the working dataset as a selectable source. | Reopen restores all working rows and the saved analysis context. Analytics may also show an existing independent draft, which keeps its own source selection. |

The blank Power Query table came from an empty `previewRows` initial state. The editor read the active rows for its column picker, but passed only a transformation response to the grid. **Run Preview** required a step, so a fresh opening showed no rows and offered no immediate preview action. The grid now starts from working data and displays a transformed sample only for the matching recipe and dataset. ## Capabilities and where to find them

| Area | Capability | Visibility and prerequisites |
| --- | --- | --- |
| Workspace | Current dataset, upload, Refine, row inspection, data-tools entry | Main destination. Working actions need an attached dataset. The header retains Save Dataset and Data Preview. |
| Data Tools | Paged rows with table and JSON display, temporary preview filters, column profile, duplicate checks, outlier detection | Main destination. Profile and duplicate checks use the loaded working rows. Outliers use the server-validated managed single-source scope. |
| Data Tools | Value validation, candidate-key checks, grouped summaries | Value validation supports required values, numbers, inclusive numeric bounds, and allowed values. Key checks accept one or more fields and report source row positions. Summaries group by one or two fields and can aggregate a numeric measure. |
| Data Tools | Fields and metrics, Data Model, REST API and SQL connection forms | Fields and metrics, REST and SQL load within the toolbox. Data Model opens its own destination. Metric editing remains in Dataset Information. |
| Power Query | Missing-value handling, row filters and limits, deduplication, text changes, renamed/reordered/removed columns, type conversion, split/merge, date extraction, grouping, pivot/unpivot, sorting | Inline editor. Step editing, ordering, preview, and apply are part of the same editor. Joined relationship models use Data Model and Analytics. |
| Data Hub | Search, metadata, registered files, open, remove, Delete All | Main destination. The manual registration form is under **Register an existing file**. Named save and update are in the working toolbar. |
| Data Model | Add or attach sources, relationship fields, candidate profiling, validation, activation, changes and deletion, Business Object definitions | Main destination. Relationship tools appear for a draft or selected relationship. Business Objects opens from the model toolbar. |
| Analytics | Analysis builder, chart and KPI configuration, filters and comparisons, drill and detail rows, dashboards, notes, and live tiles | Main destination. Use **Analysis** or **Dashboard**. Several actions require a source, a query result, or an existing tile. |
| Analytics tools | Change Explorer, visual appearance, library, draft recovery, templates, history, CSV/PDF/JSON export and print | Secondary tool rail. CSV exports analysis results. The library holds analyses, dashboards, and recovery artifacts. |
| AI and reporting | AI Chat, grounded tables and charts, artifact inspection, BI exports, dashboard drafts | Header **AI Chat**. Artifact actions appear with compatible results. |
| AI and reporting | Workflow Lab, workflow templates and execution, Narrative, conditional AI report, Autopilot, chart gallery and Whiteboard | Secondary or conditional. Use **More actions → AI Suite** for Workflow Lab and Narrative, Data Preview for Autopilot, and Analytics tools or its overflow for chart and Whiteboard actions. A report requires workflow output. |
| ML Studio | Experiment drafts, task/data selection, preparation, configuration, training, review, prediction, and local exports | Main destination. Stages unlock as the experiment advances. Its Power Query preparation refers to the experiment snapshot and remains separate from the general working dataset. |
